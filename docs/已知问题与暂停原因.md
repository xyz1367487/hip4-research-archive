# 已知问题与暂停原因

观察日期：2026年11月10日，北京时间。以下是当时对既有实现的复核结论，公开备案保留问题，不在脱敏过程中修复策略或执行逻辑。归档后的代码行号可能变化，以下按模块及调用关系定位。

## 尚未闭合的实现问题

1. **市场隔离没有完整接入实际调用链。** `v2_safety.py`虽有按市场查询未决提交的helper，merge、unwind及`c_runtime.py`开仓仍有全局未决检查。helper存在或局部测试通过不能证明不同市场已隔离。
2. **订单不再显示open，不等于已经终止。** reconcile中的兜底分类未充分覆盖缺失、空值或新增活动状态；成交数量计算也不能替代终态证明。这是代码风险，不声称交易所已经返回过这些异常状态。
3. **候选、状态与授权窗口可能不一致。** 空窗口与随后候选更新可以留下数据矛盾。授权总期限、新买入窗口和历史订单归属是不同概念，不能笼统称为授权永久失效。不得伪造扫描时间或把旧名单当新扫描结果。
4. **历史窗口fallback可能没有贯穿运行层与账本层。** 某些路径允许运行层继续尝试，但账本仍可能按后续窗口截断旧区间；窗口内已提交、窗口后成交，与窗口后新提交买入必须分开。
5. **回填幂等不能只检查key存在。** 命中已有commitment后跳过注册，可能绕开不可变payload的一致性比较；订单号绑定检查不能替代币种、数量、价格、时间和指纹一致性。未证实实际账本已经发生冲突。
6. **状态大小与恢复链路没有完整闭环。** 局部裁剪不保证整个state有界；先归档后append不是原子操作；活动路径缺失或损坏时的恢复不足。最后一次成功写入未超限，不代表下一次待写记录不会超限。

## 收益与运行结论

历史复盘将配对合并、普通退出、单边结算与奖励分开。配对毛边际为正仍可能扣费亏损；主要交易损耗可以发生在未配对库存退出。停摆期间偶然获利的单边到期结算不能证明预定做市规则有效。

停机既影响实验识别，也会形成真实持仓风险，不能把全部亏损解释为故障，更不能据此保证正常运行会盈利。止损是触发条件，不是绝对亏损上限。
